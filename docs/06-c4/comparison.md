# Сравнение C4-PlantUML и Structurizr DSL

## 1. Повторение названия контейнера

Название контейнера «Backend API» встречается в трёх `.puml`-файлах: на диаграммах Container, Component и Dynamic. В `workspace.dsl` оно указано один раз — при объявлении контейнера.

В C4-PlantUML при переименовании Backend API пришлось бы вручную менять название во всех диаграммах. В Structurizr DSL достаточно изменить его в одном месте, после чего обновлённое название будет использоваться во всех представлениях модели.

## 2. Возможности C4-PlantUML и Structurizr DSL

C4-PlantUML позволяет создавать и настраивать диаграммы непосредственно в PlantUML, использовать его синтаксис и визуальные возможности. Structurizr DSL позволяет описать единую архитектурную модель и на её основе автоматически строить несколько представлений: Context, Container и Component.

C4-PlantUML удобен для создания отдельных диаграмм с гибкой настройкой оформления. Structurizr DSL удобнее для поддержки общей модели, поскольку элементы и связи описываются один раз.

## 3. Наименее полезный уровень C4

Для мессенджера наименее полезным оказался уровень Code. Подробная структура классов уже представлена в диаграмме классов UML из ПР1. Дополнительное представление на этом уровне практически не добавляет новой архитектурной информации.

## 4. UML Component и C4 Level 3

Диаграмма компонентов UML показывает компоненты системы, их интерфейсы и зависимости. C4 Level 3 раскрывает внутреннее устройство конкретного контейнера и показывает его основные программные компоненты и связи с соседними контейнерами.

Для данного проекта я бы выбрал C4 Level 3, поскольку он помогает связать внутреннее устройство Backend API с общей архитектурой мессенджера.

## 5. Необходимость диаграммы развёртывания UML

Для текущей модели мессенджера диаграмма развёртывания UML не является обязательной. В проекте пока не определены конкретные серверы, узлы, сетевые зоны и физическое размещение компонентов. C4 Container достаточно для описания логической архитектуры системы.

Если в дальнейшем появятся требования к размещению Backend API, базы данных, очереди и обработчика сообщений на отдельных узлах, диаграмма развёртывания станет полезной.
