# ADR-0002. Асинхронная доставка сообщений через очередь

**Дата:** 2026-09-28
**Статус:** принято

## Контекст

Мессенджер должен сохранять сообщения, если получатель находится офлайн, и доставлять их после восстановления подключения. Необходимо организовать доставку так, чтобы временная недоступность получателя не блокировала отправку сообщений.

## Рассмотренные варианты

1. Выполнять доставку синхронно: сервер отправляет сообщение получателю непосредственно во время обработки запроса.
2. Использовать очередь сообщений RabbitMQ и отдельный фоновый обработчик, который выполняет доставку и обновляет статус сообщения.

## Решение

Выбран вариант 2. Backend API сохраняет сообщение и публикует событие в очередь RabbitMQ. Фоновый обработчик получает событие, выполняет доставку и обновляет статус сообщения.

## Последствия

**Плюсы:** отправка сообщения не зависит от доступности получателя; доставка может выполняться повторно; обработчик можно масштабировать независимо от API.

**Минусы:** усложняется архитектура; необходимо контролировать очередь, повторные попытки и статусы доставки.

**Что станет неверным, если решение пересмотреть:** диаграммы C4 Container и Component, динамическая диаграмма, диаграмма деятельности и диаграмма последовательности.
