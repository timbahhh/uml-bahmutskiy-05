# Сценарии использования

## ВИ-01. Отправить сообщение

**Актёры:** Пользователь (первичный), Сервис push-уведомлений (вторичный)

**Цель:** отправить сообщение другому пользователю или участникам группового чата.

**Предусловия:** пользователь зарегистрирован и авторизован; существует чат, в котором пользователь участвует.

**Постусловия (успех):** сообщение сохранено в системе и передано получателям либо помещено в очередь для последующей доставки.

**Постусловия (неуспех):** сообщение не отправлено; данные чата и ранее отправленные сообщения не изменены.

**Тип:** базовый.

**Связи:** include ВИ «Проверить участие в чате»; extend ВИ «Сохранить сообщение для офлайн-получателя».

### Основной сценарий

| № | Действие актёра | Отклик системы |
|---|---|---|
| 1 | Пользователь открывает нужный чат | 2. Система загружает историю сообщений |
| 3 | Пользователь вводит текст сообщения | 4. Система принимает текст сообщения |
| 5 | Пользователь нажимает кнопку отправки | 6. Система проверяет участие пользователя в чате |
| 7 | — | 8. Система создаёт сообщение и сохраняет его |
| 9 | — | 10. Система проверяет статус получателя |
| 11 | — | 12. Система передаёт сообщение получателю, если он онлайн |
| 13 | — | 14. Система отображает результат отправки |

### Исключения

**И-1. Пользователь не состоит в чате (шаг 6)**

Система отклоняет отправку сообщения и сообщает, что у пользователя нет доступа к этому чату. Сообщение не сохраняется.

**И-2. Сообщение пустое (шаг 4)**

Система не принимает пустое сообщение и предлагает пользователю ввести текст. Пользователь может повторить действие.

**И-3. Ошибка соединения с сервером (шаг 8)**

Система сообщает о невозможности отправки и сохраняет текст сообщения в черновике на стороне клиента. Пользователь может повторить отправку после восстановления соединения.

**И-4. Получатель находится офлайн (шаг 10)**

Система сохраняет сообщение для последующей доставки и продолжает выполнение через сценарий сохранения сообщения для офлайн-получателя.

## ВИ-02. Доставить сообщение офлайн-получателю

**Актёры:** Пользователь (первичный), Сервис push-уведомлений (вторичный)

**Цель:** обеспечить получение сообщения пользователем после восстановления подключения к мессенджеру.

**Предусловия:** пользователь зарегистрирован; ему было отправлено сообщение во время отсутствия подключения; сообщение сохранено в системе.

**Постусловия (успех):** накопленные сообщения доставлены пользователю и отмечены системой как доставленные.

**Постусловия (неуспех):** сообщения остаются сохранёнными в системе до следующей попытки доставки.

**Тип:** альтернативный.

**Связи:** extend ВИ «Отправить сообщение».

### Основной сценарий

| № | Действие актёра | Отклик системы |
|---|---|---|
| 1 | Пользователь запускает мессенджер | 2. Система устанавливает соединение с сервером |
| 3 | — | 4. Система определяет пользователя и проверяет его статус |
| 5 | — | 6. Система находит сообщения, ожидающие доставки |
| 7 | — | 8. Система передаёт накопленные сообщения пользователю |
| 9 | — | 10. Система отмечает сообщения как доставленные |
| 11 | Пользователь открывает чат | 12. Система отображает полученные сообщения |

### Исключения

**И-1. Не удалось установить соединение с сервером (шаг 2)**

Система сообщает о невозможности подключения. Сообщения остаются сохранёнными и ожидают следующей попытки доставки.

**И-2. Нет сообщений, ожидающих доставки (шаг 6)**

Система завершает проверку без передачи сообщений. Пользователь продолжает работу с мессенджером.

**И-3. Соединение прервалось во время передачи сообщений (шаг 8)**

Система сохраняет информацию о недоставленных сообщениях. После повторного подключения она возобновляет доставку, не создавая дубликатов уже доставленных сообщений.

**И-4. Ошибка сохранения статуса доставки (шаг 10)**

Система не подтверждает доставку сообщения и сохраняет информацию для повторной обработки. После восстановления работы хранилища система повторяет проверку статуса.
